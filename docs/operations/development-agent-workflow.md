# L0 Spider SCS Development Validation Workflow

## 1. Purpose

이 문서는 일반 개발 절차를 정의하지 않는다.
일반 기능 구현과 버그 수정은 루트 `AGENTS.md`의 기본 개발 및 검증 원칙을 따른다.
이 문서는 다음과 같이 추가적인 독립 검수가 실제로 필요한 경우에만 사용한다.

* 사용자가 독립 검수를 명시적으로 요청한 경우
* 중요한 인증 또는 보안 경계 변경
* 공개 API 또는 데이터 계약의 큰 변경
* 여러 subsystem에 걸쳐 회귀 위험이 명확히 큰 변경
* release 또는 명시적인 audit 업무

단순 기능 구현, 문구·스타일 변경, 로컬 버그 수정 또는 기존 계약을 유지하는 내부 변경에는 이 workflow를 적용하지 않는다.

## 2. Review Timing

독립 검수는 구현 중간에 수행하지 않는다.
메인 개발 에이전트가 다음을 완료한 안정된 최종 diff에서만 검수를 시작한다.

1. 요청된 구현 완료
2. 변경 범위에 직접 관련된 검증 완료
3. 필요한 경우 직접 영향받는 문서 또는 계약 반영
4. 최종 변경 범위 확인

독립 검수는 업무당 최대 1회만 수행한다.
검수 이후 단순 문서 정리나 비차단 개선을 이유로 자동 재검수를 수행하지 않는다.

## 3. Review Input

독립 검수에는 판단에 필요한 최소 정보만 제공한다.

* 원 사용자 요구사항
* 검수 대상 변경 범위
* 기준 branch와 필요 시 commit
* 최종 diff
* 메인 에이전트가 수행한 주요 검증 결과
* 판단에 중요한 미실행 검증이 있는 경우 그 사유

관련 없는 과거 작업, 전체 프로젝트 문서, 전체 테스트 로그 또는 불필요한 운영 정보는 전달하지 않는다.
검수자는 제공된 정보와 최종 diff를 기준으로 시작하고, 구체적인 판단에 필요한 파일만 선택적으로 읽는다.

## 4. Independent Review Scope

실제 검수 범위와 판정 기준은 `.codex/agents/pre-build-review.toml`을 따른다.
메인 에이전트는 reviewer에게 저장소 전체 감사나 현재 변경과 관계없는 검토를 추가로 요구하지 않는다.

## 5. Review Result

검수 결과는 `PASS` 또는 `BLOCKER`다.
판정 기준은 `.codex/agents/pre-build-review.toml`을 따른다.

- `PASS` → 완료 보고로 진행한다.
- `BLOCKER` → 발견 사항을 메인 에이전트가 일괄 수정하고 직접 관련된 검증을 수행한다

## 6. BLOCKER Handling

`BLOCKER`가 반환되면 메인 개발 에이전트가 발견 사항을 일괄 수정하고 직접 관련된 검증을 수행한다.
수정 후 독립 검수를 자동으로 다시 호출하지 않는다.
최종 보고에서는 다음을 구분한다.

* 독립 검수에서 발견된 사항
* 메인 에이전트가 수행한 수정
* 수정 후 수행한 검증
* 재검수를 수행하지 않았다는 사실

사용자가 수정 후 새로운 독립 검수를 명시적으로 요청한 경우에만 별도 업무로 다시 수행한다.

## 7. Reviewer Restrictions

`pre-build-review`의 실행 권한과 금지 사항은 `.codex/agents/pre-build-review.toml`을 따른다.
메인 에이전트는 검수를 위해 reviewer의 권한을 확대하거나 다른 agent 또는 CLI로 우회하지 않는다.

## 8. Execution Limits

- 독립 검수는 필요한 업무에서 최대 1회 수행한다.
- 구현 중간 또는 수정 후 자동 재검수는 수행하지 않는다.
- 권한이나 환경 문제로 검수를 수행할 수 없으면 다른 agent, CLI 또는 권한 변경으로 우회하지 않는다.

중요한 미검수 사항과 이유는 최종 보고에 남긴다.
